# v0.9 — Queue and Media Design

Status: proposed
Date: 2026-10-01
Starting point: v0.8.0

## Problem

v0.8 gave the GUI a per-URL batch table, but the underlying capability is still
"run these URLs one after another." Four gaps:

1. **No queue.** A batch is not a queue: it cannot be paused, its progress does
   not survive a restart, a long in-flight download cannot be aborted, and there
   is no way to add work while it is running.
2. **No playlists.** A playlist or channel URL is extracted as a single item;
   yt-dlp can expand it, but nothing in this tool asks it to.
3. **No media extras.** Subtitles and embedded thumbnails are common enough that
   not offering them is a missing feature, not a nicety.
4. **No format picker.** Users who want a specific stream must take the
   opinionated default selector.

## Goals

- A real queue: persistent, pausable, resumable, cancellable, with mid-download
  abort.
- Playlist URLs expand into queue items, bounded by an explicit cap.
- Optional subtitle download and thumbnail embedding.
- A format picker that shows what yt-dlp offers and downloads the chosen stream.

## Non-goals

- MCP server, package managers, distribution (v1.0).
- Cloud sync, accounts, telemetry.
- Changing the download-result contract's schema version (`1.0` stays; one new
  error category is added).

## Decisions taken

- **The queue replaces the batch tab.** There is one way to download many URLs.
- **Pause and cancel preempt at item boundaries AND mid-download.** An in-flight
  yt-dlp call is aborted through its progress hook.
- **All four roadmap items ship in v0.9**, built in three waves.
- **Persistence is a JSON file** in the app config directory. The CLI and GUI
  share it; no QSettings for queue state.
- **Playlist expansion happens before enqueue.** The download core stays
  one-URL/one-file.
- **Format picking surfaces yt-dlp's own enumeration.** We do not parse formats
  ourselves.

## Architecture

### Wave 1 — Queue core (the risk)

**`core/download.py` changes**

```python
class DownloadCancelled(Exception):
    """Raised inside the progress hook when cancellation is requested."""


def download_one(url, outtmpl, output_type, convert, target_resolution,
                 cookies_file=None, progress=None, cancel=None,
                 subtitles=False, embed_thumbnail=False, format_id=None):
```

- `cancel: Optional[Callable[[], bool]]`. Checked in the progress hook; when it
  returns True, raise `DownloadCancelled`.
- On `DownloadCancelled`: delete the artifact and any `<name>*.part` siblings
  created by this run, then return `error_result("cancelled", "Cancelled.", url)`.
  Only files this run created are removed; pre-existing files are never touched.
- `subtitles`, `embed_thumbnail`, `format_id` are new optional parameters that
  shape `_nle_ydl_opts` (wave 3 uses them; wave 1 only adds the signature).

**New: `core/queue.py`** (no Qt, no threads inside)

```python
@dataclass
class QueueJob:
    id: str
    url: str
    state: str            # pending|running|done|failed|cancelled|paused
    message: str = ""
    path: Optional[str] = None
    bytes: int = 0
    height: int = 0
    attempts: int = 0
    options: dict = field(default_factory=dict)   # output_type, convert,
                                                  # target_resolution, etc.


class QueueStore:
    def __init__(self, path: str): ...
    def load(self) -> None
    def save(self) -> None
    def to_dict(self) -> dict          # {"version": 1, "jobs": [...]}
    @classmethod
    def from_dict(cls, data: dict) -> "QueueStore"


class Queue:
    def add(self, url, options) -> QueueJob
    def add_many(self, urls, options) -> list[QueueJob]
    def next_pending(self) -> Optional[QueueJob]
    def run_once(self, executor) -> Optional[QueueJob]
    def pause(self) / resume(self)
    def cancel_job(self, job_id) / cancel_all(self)
    @property
    def paused(self) -> bool
```

- `run_once(executor)` pulls the next `pending` job, marks it `running`, calls
  `executor(job)` (a callable wrapping `download_one`), records the outcome in
  the job, and returns it. It runs **one** item. The GUI worker loops it; the
  CLI loops it inline.
- Persistence: `{"version": 1, "paused": bool, "jobs": [...]}`. A `version`
  field so a future format change can migrate rather than crash.
- `jobs` stores `created_at` (ISO string) for stable ordering across restarts.
- **When saving happens**: `QueueStore.save()` is explicit. The GUI worker calls
  it after each job transition; the CLI calls it after each command. There is no
  autosave-on-mutation, so a write never happens on a hot path and the core stays
  free of filesystem surprises.

**New: `workers/queue_worker.py`** — a `QThread` that loops `queue.run_once`
until the queue is empty or paused, emitting `(job_id, state, job)` per
transition and a per-item percentage. It owns a `threading.Event` for cancel.

**CLI**: `socialclip queue add|run|list|clear` — `run` drains the queue inline
(useful for agents: enqueue many, then run). Queue state file is shared with the
GUI.

**GUI**: the batch tab becomes the queue tab. The v0.8 table gains a per-row
state column driven by the worker, a Pause/Resume button, per-row Cancel, and
"Add URLs" appends to the persisted queue.

### Wave 2 — Playlists

`core/queue.py` gains expansion at add time:

```python
def expand_url(url, cookies_file=None, max_items=0, flat=True) -> list[str]
```

- Uses yt-dlp with `extract_flat` to list entries without downloading; returns
  entry URLs. `flat=True` means "do not descend into nested playlists".
- **`max_items=0` (the default) means do not expand at all** — the URL is
  returned as-is. A positive `max_items` expands and truncates to that many
  entries. This makes the default behavior identical to today; expansion is
  always opt-in and always bounded.
- A URL that is not a playlist returns `[url]`.
- GUI: a playlist URL added to the queue offers "Expand playlist (N items)";
  choosing it calls `expand_url` with a cap the user sets (default 50).
- The cap is explicit and default-off, per the roadmap.

### Wave 3 — Media extras and format picker

**`QueueJob.options` keys** (all optional; absent = current default behavior):

```
output_type: "MP4" | "MP3"
convert: bool
target_resolution: int
cookies_file: str
format_id: str            # wave 3; overrides the default selector
subtitles: bool           # wave 3
embed_thumbnail: bool     # wave 3
```

**`core/media.py`**

```python
def list_formats(url, cookies_file=None) -> list[dict]
    # each: {"id", "ext", "height", "vcodec", "acodec", "filesize", "note"}

def list_subtitles(url, cookies_file=None) -> list[dict]
    # each: {"lang", "name", "auto": bool}
```

- `list_formats` reads yt-dlp's `formats` list; nothing is inferred.
- `download_one`'s `format_id` overrides `_nle_safe_format_selector()` when set.
- `subtitles=True` sets yt-dlp's subtitle options (write auto-subs, convert to
  `srt`); `embed_thumbnail=True` adds the thumbnail embed postprocessor.

**GUI**: a "Formats…" action on a fetched item opens a dialog listing
`list_formats`; choosing one stores `format_id` on the job. Checkboxes for
"Download subtitles" and "Embed thumbnail" join the output options and persist
via QSettings like the other options.

**CLI**: `--format-id`, `--subtitles`, `--embed-thumbnail` on `download` and on
`queue add`.

## Error handling

- `run_once` never raises: it records `failed` with the classified message.
- A queue file that is missing, unreadable, or of an unknown `version` loads as
  empty rather than crashing; the bad file is left on disk for inspection.
- Cancellation is a normal outcome (`state == "cancelled"`, category
  `"cancelled"`), never an error dialog.
- Playlist expansion failure degrades to the single URL.

## Testing

- **Pure logic, pytest**: `Queue` state transitions, `run_once` with an injected
  executor, `QueueStore` round-trip and version handling, `expand_url` with an
  injected extractor, `list_formats` with a stub, the cancel hook (a `cancel`
  callable that flips mid-run aborts and cleans up).
- **CLI**: `queue add/list/run` against a temp queue file; `--json` purity holds.
- **Worker/UI**: headless construction and a manual launch. GUI not unit-tested
  beyond pure helpers, per repo convention.
- The cancel-hook test uses a fake executor and a pre-created temp file, asserting
  the file is removed and the result is `cancelled`.

## Risks

- **Mid-download abort can leave partial files if cleanup misses a suffix.**
  Mitigated by removing the artifact plus any `<base>*.part` in the output dir
  that this run created, and by the test above.
- **Queue persistence across a pause is not true resumption.** A partly
  downloaded item restarts on resume; it only continues seamlessly if yt-dlp's
  `.part` file is still present on the same machine. The spec states this; the
  UI must not claim "resume from 40%".
- **Playlist expansion can explode into thousands of items.** Mitigated by an
  explicit cap, default off.
- **The queue tab re-touches a surface just redesigned in v0.8.** Accepted; the
  v0.8 table is the right base and the change is additive (state column, buttons).
- **Four subsystems in one release.** Mitigated by three waves, each shippable
  and independently reviewed.

## Deferred

- Per-item percentage in the v0.8 batch table becomes moot (the queue ships it).
- True cross-session resume of a partial download.
- Format picker presets / saved preferences.
- MCP server and distribution (v1.0).
