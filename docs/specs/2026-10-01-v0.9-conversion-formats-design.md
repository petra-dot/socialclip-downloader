# v0.9 Companion — Conversion Formats Design

Status: proposed
Date: 2026-10-01
Extends: `docs/specs/2026-10-01-v0.9-queue-media-design.md` (adds to the same
v0.9 release, which ships on one branch)

## Problem

The converter supports three outputs (`MP4`, `MP3`, `WAV`) chosen by hardcoded
`if output_type == "MP3"` branches across `core/convert.py`,
`utils/file_utils.py`, `ui/convert_tab.py`, and `cli.py`. ffmpeg supports
hundreds of containers and codecs; users want the common ones without
hand-writing ffmpeg commands.

Two things are wrong beyond the short list:

1. **Every conversion re-encodes.** There is no way to repackage streams
   (remux), so changing a container needlessly re-encodes and loses quality.
2. **The format list is duplicated in four places**, so adding one is four edits
   and easy to half-do.

## Goals

- A curated set of output formats covering what people actually convert to.
- Remux when the source streams already fit the target container; transcode
  otherwise; user can override.
- One place that defines the formats.

## Non-goals

- Exposing every encoder ffmpeg reports.
- Per-stream codec/quality/CRF controls.
- Changing the download result contract (`schema_version` stays `"1.0"`).

## Decisions taken

- **Curated container/audio list** (14), not "everything ffmpeg knows".
- **Auto by default, user-overridable**: remux when compatible, else transcode;
  a tri-state toggle (auto / copy / re-encode).
- **Conversion is added to the current v0.9 branch** before it merges, so v0.9
  ships as "queue + conversion".
- **Existing three-format behaviour is preserved byte-for-byte**; the new
  parameters are additive.

## Architecture

### New: `core/formats.py`

```python
@dataclass(frozen=True)
class Format:
    key: str          # "mkv"      — CLI value and dict key
    label: str        # "MKV (Matroska)"
    kind: str         # "video" | "audio"
    container: str    # ffmpeg -f value, "" = infer from extension
    vcodec: str       # codec an auto-transcode uses; "" iff kind == "audio"
    acodec: str       # codec an auto-transcode uses
    extension: str    # "mkv"
    remux_v: tuple    # vcodecs this container can hold without re-encoding
    remux_a: tuple    # acodecs this container can hold without re-encoding


FORMATS: list[Format]
def get(key: str) -> Format | None
def for_kind(kind: str) -> list[Format]
def keys() -> list[str]
```

Invariants the tests assert:

- keys are unique and lowercase;
- `kind` is `"video"` or `"audio"`;
- `vcodec == ""` if and only if `kind == "audio"`;
- `acodec` is non-empty for every format;
- `extension` is non-empty;
- `remux_v` is empty for audio formats; `remux_a` is the set of audio codecs the
  container accepts as-is.

**Remux legality is defined by the container allow-lists, not by judgement in
code.** A remux is planned when the source `vcodec` is in `target.remux_v` (for
video targets) and the source `acodec` is in `target.remux_a`. Examples:
`mkv.remux_v = ("h264", "hevc", "vp9", "av1")`, `mp4.remux_v = ("h264",
"hevc", "av1")` (not vp9), `webm.remux_v = ("vp9", "av1")` and
`webm.remux_a = ("opus", "vorbis")`, `gif.remux_v = ()` (never), `mp3.remux_a =
("mp3",)`.

The curated 14:

- video: `mp4`, `mkv`, `webm`, `mov`, `avi`, `gif`
- audio: `mp3`, `m4a`, `wav`, `flac`, `ogg`, `opus`, `aac`, `wma`

Rules encoded per format: whether a remux is ever possible (`gif` no, `wav` only
from PCM, lossy targets no), and the codec pair an auto-transcode uses
(`mkv` = copy-if-possible else h264/aac; `webm` = vp9/opus; `flac` = flac; etc.).

### New: `core/probe.py`

```python
def probe_media(path, runner=None) -> dict
    # {"vcodec": str, "acodec": str, "height": int, "container": str}
    # never raises; missing fields are ""
```

One `ffprobe` call, JSON output, parsed once. `ffprobe_get_height` in
`utils/ydl_opts.py` stays for compatibility; `probe_media` supersedes it in the
converter. If ffprobe is unavailable, fall back to the existing
`_ffmpeg_height` path and return empty codecs (which forces a transcode plan).

### Changed: `core/convert.py`

```python
class ConvertPlan(NamedTuple):
    mode: str        # "remux" | "transcode"
    vcodec: str      # "copy" or a codec
    acodec: str
    container: str

def plan_conversion(src_info: dict, target: Format, copy_streams=None) -> ConvertPlan
def convert_file(input_path, output_type=None, target_resolution=None,
                 target_format=None, copy_streams=None) -> DownloadResult
```

- `plan_conversion` is **pure** and gets the test suite.
- `copy_streams=None` (auto): remux when the source `vcodec` is in
  `target.remux_v` (video targets) and the source `acodec` is in
  `target.remux_a`; else transcode to the format's codec pair. The allow-lists
  are the sole authority — no ad-hoc compatibility guessing.
- `copy_streams=True`: force remux; if the target cannot hold the source codecs,
  return an error result naming the mismatch (no silent fallback).
- `copy_streams=False`: force transcode.
- Audio target from a video source: video stream is dropped (`-vn`), audio is
  copied if the container/codec permits, else transcoded.
- `target_format=None` keeps today's path exactly (`output_type` in
  `MP3`/`WAV`/`MP4` + optional resolution), so existing callers are untouched.

### Changed: UI and CLI

- **Convert tab**: "Convert to" is built from `formats.for_kind` grouped
  video-then-audio; the resolution combo is disabled when the target is audio
  or when copy is forced. A **"Copy streams (fast, lossless)"** checkbox with
  three states: Auto (default) / Copy / Re-encode.
- **CLI**: `socialclip convert FILE --to mkv [--copy|--no-copy] [--resolution N]`.
  `--to` accepts the format keys; an unknown key exits 2 and lists valid keys.
  `--resolution` is ignored (with a note) for audio targets.
- The result `message` names the mode: "Remuxed to ..." vs "Converted to ...".

## Error handling

- `probe_media` never raises; a failed probe yields empty codecs, which plans a
  transcode (the reliable path).
- A forced remux that cannot work returns `error_result("format", ...)` naming
  the source and target codecs.
- ffmpeg non-zero returns `error_result("ffmpeg", stderr, ...)` as today.
- Unknown format key from the CLI is a usage error (exit 2), not a crash.

## Testing

- **Pure**: `FORMATS` invariants (unique keys; non-empty extensions; every audio
  format has an `acodec`; every video format has an `acodec` too since video
  carries audio); `plan_conversion` truth table (auto remux when compatible,
  transcode otherwise, forced modes, gif never remuxes, audio-from-video drops
  video); `probe_media` parsing against a captured ffprobe JSON fixture.
- **Existing**: `tests/test_core_convert.py`'s three MP3/WAV/MP4 tests must stay
  green unchanged — they prove the additive promise.
- **CLI**: `--to mkv` builds the right plan (assert on a stubbed runner);
  unknown `--to` exits 2 and prints valid keys.
- **GUI**: combo populated from the registry, resolution disabled for audio.
  Headless construction plus one manual launch; GUI not unit-tested, per
  convention.

## Risks

- **Remux can produce a technically valid but unplayable file** in odd
  container/codec combinations. Mitigated by only planning a remux when the
  codec pair is known-legal for the container, and by the auto default choosing
  transcode when unsure.
- **The curated list will not satisfy everyone.** Accepted; the registry makes
  adding a format a one-row change.
- **Two conversion code paths now exist in `convert_file`.** Mitigated by making
  the new path strictly additive and keeping the existing three-format tests as
  the regression guard.
- **This grows an already-large v0.9 branch.** Accepted by decision; the final
  review covers queue + conversion together.

## Deferred

- Codec/quality/CRF selection.
- Batch conversion of a folder.
- Format-specific advanced flags (two-pass, hardware encoders).

## Carried from the v0.9 queue review (fix before merge)

These three defects were found by an OpenCodeReview delegation pass over the
queue commits and are deliberately deferred to the end of the v0.9 work, so they
are fixed together with the conversion changes rather than in a separate pass.

1. **HIGH — `workers/queue_worker.py` emits the live `QueueJob` object across
   threads.** `_executor` emits `job_signal(job.id, job.state, job)` and then
   `run_once` mutates the same object to its terminal state; a queued delivery to
   the GUI thread can therefore read the final state under a `running` event, so
   the row renders the wrong status. Fix: emit a snapshot
   (`dataclasses.replace(job)`) or a plain tuple of the fields the slot needs,
   not the live object.
2. **MEDIUM — `core/queue.py` `save()` uses a fixed `.tmp` name.** The GUI and
   the CLI share one queue file and both save; two concurrent writers can
   `os.replace` each other's partial file and lose a job. Fix: per-process tmp
   name (`f"{path}.{os.getpid()}.tmp"`) or a lock.
3. **MEDIUM — a non-cancel crash mid-download leaves a partial file behind with
   no cleanup.** Cancellation cleans up via `_cleanup_partial`; any other
   exception marks the job `failed` and orphans whatever yt-dlp wrote. Fix:
   apply the same cleanup on the generic exception path, or record the in-flight
   path on the job so it can be reclaimed.

Each fix needs a covering test. After they land, re-run an OCR delegation pass to
confirm all three are resolved.
