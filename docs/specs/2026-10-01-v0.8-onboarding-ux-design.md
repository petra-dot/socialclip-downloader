# v0.8 — Onboarding and UX Design

Status: proposed
Date: 2026-10-01
Starting point: v0.7.0

## Problem

v0.7 made the tool useful to agents (headless core + `socialclip` CLI). The
GUI, however, is still a v0.6-shaped tool with v0.7 internals. Four concrete
problems:

1. **Download is gated on a manual step.** The Download button refuses until
   Fetch has succeeded ("Click Fetch first"), so the shortest path to one
   video is: paste, click Fetch, wait, click Download.
2. **The batch tab shows a wall of text, not state.** URLs live in a free-text
   box and progress is a stream of log lines. You cannot see which item is
   running, which failed, or how far along the current item is.
3. **There is no first-run or diagnostic surface in the GUI.** A new user gets
   an empty window and no explanation; when something is wrong (no ffmpeg, no
   cookies) the only signal is a failing download.
4. **"Where did my file go" is unanswered.** After a download there is no link
   to the output.

## Goals

- Paste a URL and have the app start working, with metadata still shown before
  the download completes.
- See per-item state for a batch.
- Get told what is broken before a download fails.
- Reach the downloaded file in one click.

## Non-goals

- Changing the core download/convert behavior or the `--json` result contract
  (only `doctor --json` changes, additively).
- A dark theme, notifications, or tray integration (later releases).
- Rewriting the single tab's layout beyond the changes named here.

## Decisions taken

- **Paste-and-go**: auto-fetch when the URL box changes to a plausible URL
  (debounced), plus clipboard auto-fill on focus. The Fetch button remains for
  manual retry. Download semantics are unchanged: metadata is still fetched and
  shown first, and Download still needs it.
- **Batch**: the free-text box is replaced by a per-URL table. A **Bulk paste
  dialog** is kept as the fallback for pasting many URLs at once.
- **Doctor**: checks are extended (ffmpeg version, cookie files per platform,
  network reachability) and surfaced in a GUI dialog.
- **`doctor --json` schema**: extended additively; `schema_version` jumps to
  `1.1`. No fields are removed.

## Architecture

### New: `core/doctor.py`

```python
def run_checks(env=None, which=None, exists=None, probe=None) -> dict
```

Returns a structured report and never raises:

```json
{
  "schema_version": "1.1",
  "ffmpeg": {"found": true, "path": "/usr/local/bin/ffmpeg", "version": "6.1.1"},
  "cookies": [
    {"platform": "youtube", "found": true, "path": "D:/app/youtube_cookies.txt"},
    {"platform": "douyin", "found": false, "path": null}
  ],
  "network": {"ok": true, "detail": "example.com reachable"}
}
```

- `ffmpeg`: reuse `utils.ffmpeg.find_ffmpeg`; version from the first line of
  `ffmpeg -version`. Version is `null` if the call fails.
- `cookies`: one entry per platform in `PLATFORM_NAMES`, using
  `default_cookie_dir()` and `get_cookie_path`. Path is `null` when absent.
- `network`: a single bounded HTTP request (short timeout). Returns
  `{"ok": null, ...}` on any failure or when skipped.

Injectable parameters (all default to the real implementation):

- `env`, `which`, `exists`: passed through to the ffmpeg and cookie lookups.
- `probe: Callable[[], tuple[bool, str]]`: returns `(ok, detail)`. Tests inject
  a stub; the default performs the bounded HTTP request. `run_checks` catches
  any exception from `probe` and records `{"ok": None, "detail": str(exc)}`.

`schema_version` note: this is the **doctor report** version and is `"1.1"`.
The **download result** contract (`core.manifest.DownloadResult`) stays at
`"1.0"`; the two versions are independent.

### New: `core/` helpers

- `core/paths.py` (or extend `utils/file_utils.py`): `reveal_in_folder(path)`
  reveals the file in the OS file manager, selecting it where the platform
  supports selection: `explorer /select,<path>` (Windows), `open -R <path>`
  (macOS), `xdg-open <dir>` (Linux, opens the parent directory). The command
  **builder** is pure and tested; the runner is a thin subprocess call. The
  path passed is always the **final artifact** (the `.mp3`/converted file when
  post-processing ran, otherwise the downloaded file).
- URL heuristic: `looks_like_url(text) -> bool` (pure, tested). Plausible =
  has a scheme, or matches `host.tld` with an optional path.

### Changed: batch worker contract

`workers/batch_worker.py` gains one additive signal:

```python
item_signal = QtCore.pyqtSignal(int, str, object)  # (index, state, result)
```

- `state` in `{"running", "done", "failed", "cancelled"}`.
- `result` is a `DownloadResult`, or `None` on failure (message is in
  `result.message`).
- `status_signal(str)` and `finished_signal(str)` are unchanged; the log pane
  still consumes them.
- Per-item progress: the worker forwards a `progress` callback per item so the
  running row can show a percentage.

### Changed: `cli.py doctor`

`_cmd_doctor` calls `core.doctor.run_checks()` and emits the report (JSON or
human). `schema_version` in the report is `1.1`. The existing `/manifest-schema`
command documents result objects; the doctor report shape is documented in the
README, not the result schema.

### Changed: UI

**Single tab** (`ui/single_tab.py`)
- `url_input.textChanged` → debounce timer (~600ms) → if `looks_like_url`, run
  the existing fetch path. The `_fetch_seq` guard already handles races.
- On `focusInEvent` / tab activation: if empty, fill from clipboard when the
  clipboard holds a URL.
- After a successful download or conversion: show an "Open folder" button wired
  to `reveal_in_folder`.
- Progress bar hides only after post-processing completes (no premature 100%).

**Batch tab** (`ui/batch_tab.py`)
- Replace the `QTextEdit` with a `QTableWidget` (columns: URL, Status, Detail).
- Add URLs: "Add URLs" button opens the **Bulk paste dialog** (multi-line text
  box, one URL per line, appends rows). Pasting into the table also splits on
  newlines.
- Rows update from `item_signal`; the running row shows `running <pct>%`.
- Cancel (added in v0.7.0) marks remaining rows `cancelled`.
- The log pane stays below the table.

**Onboarding** (`ui/main_window.py`, `ui/welcome.py`)
- First-run dialog shown once (`QSettings "first_run_done"`): what the app does,
  the default save location, ffmpeg status from `run_checks`, and the cookie
  note.
- A menu item (Help → Doctor) opens a dialog rendering `run_checks()`.

## Error handling

- `run_checks` never raises; each check independently degrades to a `false`/
  `null` result and a detail string.
- Network probe failures are reported, never fatal, and never block the dialog.
- Auto-fetch failures reuse the existing `classify_error` copy; a failed
  auto-fetch must not pop a modal (it logs, as manual Fetch does today).

## Testing

- **Pure logic, pytest**: `run_checks` with injected ffmpeg/which/network;
  `looks_like_url`; the `reveal_in_folder` command builder per platform;
  `schema_version == "1.1"` and the report keys.
- **CLI**: `doctor --json` asserts the new shape and version; existing CLI tests
  must stay green (update `test_cli.py` doctor expectations if they assert the
  old shape).
- **Worker/UI**: headless construction checks (widgets exist, signals wired,
  fresh state correct) plus one manual launch. GUI is not unit-tested, per repo
  convention recorded in AGENTS.md.
- All existing tests stay green.

## Risks

- **Auto-fetch on every keystroke could spam the network.** Mitigated by the
  URL-plausibility gate, debounce, and the existing in-flight guard.
- **The table loses the immediacy of a text box.** Mitigated by the Bulk paste
  dialog and paste-splitting.
- **`doctor --json` shape change** is additive with a version bump, but any
  consumer pinned to the old two-key shape breaks. This is accepted; the
  README documents the new shape.
- **Network probe in CI** must not depend on connectivity: it is injectable and
  the test asserts the injected path, never the real network.

## Deferred

- Dark theme, system notifications, tray icon.
- Batch queue persistence across restarts.
- Per-tab cookie path unification (the shared `cookies_file_ref` wart).
