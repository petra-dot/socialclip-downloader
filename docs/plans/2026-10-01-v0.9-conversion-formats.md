# v0.9 Conversion Formats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a curated ffmpeg format registry with remux/transcode planning to the converter, expose it in the GUI and CLI, and clear the three defects carried from the queue review.

**Architecture:** A pure `core/formats.py` table defines the formats and the codecs each container can hold without re-encoding. A pure `plan_conversion` maps a probed source plus a target Format to a `ConvertPlan` (remux or transcode). `convert_file` executes that plan. The existing three-format path is preserved and its tests are the regression guard.

**Tech Stack:** Python 3.8+, ffmpeg/ffprobe, PyQt5 (GUI), argparse (CLI), pytest. No new dependencies.

**Spec:** `docs/specs/2026-10-01-v0.9-conversion-formats-design.md` and the three carried defects at its end.

## Global Constraints

- `core/` must not import PyQt5 (guarded by `tests/test_core_isolation.py`).
- The download result contract `schema_version` stays `"1.0"`.
- **Existing behaviour is byte-identical:** `convert_file(path, "MP3"|"WAV"|"MP4", resolution)` behaves exactly as today. `tests/test_core_convert.py` must pass unchanged.
- The three-format path must not be rewritten — the new parameters are additive.
- `vcodec == ""` iff `kind == "audio"`; `acodec` non-empty for every format.
- Remux legality is decided by the per-format allow-lists, never by ad-hoc guessing.
- Each deferred-defect fix needs a covering test.
- Conventional Commits. Work on the existing `feat/v0.9-queue` branch.

```python
ConvertPlan = namedtuple("ConvertPlan", "mode vcodec acodec container")


def plan_conversion(src_info, target, copy_streams=None):
    v = (src_info or {}).get("vcodec", "") or ""
    a = (src_info or {}).get("acodec", "") or ""

    if target.kind == "audio":
        if copy_streams is False or a not in target.remux_a:
            return ConvertPlan("transcode", "", target.acodec, target.container)
        return ConvertPlan("remux", "", "copy", target.container)

    v_ok = v in target.remux_v
    a_ok = a in target.remux_a
    if copy_streams is True:
        return ConvertPlan("remux", "copy", "copy", target.container)
    if copy_streams is None and v_ok and a_ok and target.remux_v:
        return ConvertPlan("remux", "copy", "copy", target.container)
    return ConvertPlan("transcode", target.vcodec, target.acodec, target.container)
```

`copy_streams=True` forces remux regardless (the caller asked; ffmpeg will fail
clearly if it cannot). `gif` has an empty `remux_v`, so it never remuxes.

`--to` changes from a fixed `choices=["mp4","mp3","wav"]` list to a **format

- `--copy` / `--no-copy` (`store_true`/`store_false` into `copy_streams`,
  default `None`) only apply when `--to` is given; passing them without `--to` is
  a usage error with a clear message.

path (not the legacy one): monkeypatch `convert_file` and assert it received
`target_format == "mp4"` and `output_type is None`.

Note the behaviour change for existing users: `--to wav` now means the WAV
*format* (transcode to PCM) rather than the legacy WAV `output_type`; the output
is the same audio, so the effect is equivalent, but the code path differs. State
this in the CHANGELOG.
